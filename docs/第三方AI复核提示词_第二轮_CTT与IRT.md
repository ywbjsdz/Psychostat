### 4. 第二轮任务（按价值排序）

#### G1（最高价值）多维 GPCM/MGPCM 的 L3 独立实现对照

**为什么**：`ltm` 只覆盖单维 2PL/GRM，所以**多维 GPCM 至今没有任何独立实现对照**
（我方 L1 只是"从参数表代数自洽"，L3 是空白）。这是整份校对最大的洞。

**做法**：用 `TAM`（推荐）或 `sirt` 对 `irt_G` 的数据重跑多维 GPCM，与工具输出对照：

- 数据 `examples/simulated_datasets/irt_G_multidimensional_gpcm_n900_items24.csv`
- 工具参数 `outputs/` 下 `irt_G_config_cifa` / `irt_G_config_eifa` 生成目录里的
  `*_item_parameters.csv`（`a1..a3`、`d1..d4`、`b_d1..b_d4`）
- 对照口径：**工具的 `b_dk` 是台阶难度 = 相邻类别截距之差 ÷ MDISC**（Muraki 口径），
  `a_d` 是维度斜率。请先核对你的实现与这套口径的换算，再比 **相关 + 平均偏差**
  （不要直接比绝对值：潜在量尺的识别约束不同）。
- 判据建议：a 的 r ≥ .95；台阶 b 的 r ≥ .95 且 |平均偏差| ≤ .05；**并说明你为何选这个判据**。

**已知陷阱（我们踩过）**：
① `TAM` 的 `B` 矩阵含**类别乘子**（与 mirt 的 `ak*` 同源）——不要把乘子当维度载荷
（我方曾因此把单维 GPCM 的 MDISC 算成 5.536，而该题 a 只有 0.805）；
② `ltm::grm()` 与 `ltm::tpm()` **没有公式接口**（第一个形参就是 `data`），写成 `grm(X ~ z1)` 会报
"'data' must be either a numeric matrix or a data.frame"；
③ 多维下 mirt 的能力估计 SE 与"按主维度分组的条件切面 TIF"**不存在等式关系**，不要拿它们互验。

#### G2 CFA 的 L3 独立复核（`OpenMx` 或 `semTools`）

**为什么**：CTT 的 CFA 载荷至今只有 L1（用工具自己的 `standardized_loading` 代闭式算 CR/AVE）
与 L2（对真值恢复 r=.872），**没有第二实现**。

- 数据 `examples/simulated_datasets/ctt_B_full_survey_n500_items20.csv`
- 映射 `ctt_B_cfa_mapping.csv`；配置 `ctt_B_config.yaml`
- 工具输出：该配置生成目录里的 `05_cfa_loadings.csv`、`05_cfa_model_syntax.lav`
- **关键前置**：工具的估计口径是——题目唯一取值 ≤10 时用 **WLSMV（有序）**，否则 **ML**；
  `std.lv = TRUE`（因子方差固定为 1）。你必须**对齐同一口径**再比，否则差异来自口径不是实现。
- 产出：标准化载荷的 r、RMSE、最大单题偏差；并说明你是否能复现工具的估计量选择。

#### G3 模型拟合指标的第二实现或文档级核对

**为什么**：`M2*`、`SRMSR`、`TLI/CFI` 从未被独立复算，BIC 排名也只验了"表内自洽"。

- 目标文件：结果目录里的 `*_model_comparison.csv`
- 做法二选一（说明你选了哪种）：(a) 用 `TAM::tam.modelfit` 或 `sirt` 复算 M2/SRMSR；
  (b) 从 `mirt` 文档/源码逐项核对定义与自由度口径，给出"工具的值在定义上是否可能正确"的判断。
- 产出：能复算的给数值；不能复算的明确写"未能复算，原因是……"，**不要用"看起来合理"代替复算**。

#### G4 报告层忠实性（**完全未被任何一轮覆盖**）

**为什么**：研究者最终读的是报告，不是 CSV。至今没有任何人查过"报告里的数字是否等于 CSV 里的数字"。
这是"会写进论文"的最后一道关口。

- 在**第 2 节白名单里的 5 个结果目录**上做（这 5 个都是走启动器生成的，同时具备
  `*.csv` + `report_zh.md` / `*_report_zh.docx` / `*_report_zh.html`）。
- 做法：把每个目录的 CSV 与同目录的中文报告**对读**（docx 用 `python-docx` 抽文本，
  html 直接读源码或抽文本）。每个目录**至少抽查 3 个统计量**（例如 N、α/信度、
  关键拟合指标、题目参数、模型名），逐个核对是否一致。
- 特别检查：① 报告正文里的**结论句**是否与表格数据方向一致；② 数字的**小数位与四舍五入**是否自洽；
  ③ 表格是否**漏行/错列**；④ 中英文报告是否互相矛盾；⑤ 报告里出现的模型名/维度数是否与实际选中的模型一致。
- 产出：一张"目录 × 抽查项 × 一致/不一致"的表；不一致的给最小复现。

#### G5 `empirical_rxx` 与近似式的口径差异（我方目前只报告、不判定）

**为什么**：我方 L1 的 I16 发现工具（`mirt::empirical_rxx`）与近似式 `1−mean(SE²)/var(θ)`
差 0.0095～0.1125，但当时无法判定"差多少算正常"，所以只报告不判定。这个悬而未决的项应该被解决。

- 可用材料：`deparse(mirt::empirical_rxx)`、`deparse(mirt::marginal_rxx)`（直接从已装的 mirt 里取函数体）、
  任一结果目录的 `*_reliability.csv` 与 `*_ability_estimates.csv`。
- 做法：从函数体推导两者的**定义差异**（例如：是否用后验方差、是否按维度、是否用边缘分布、
  分母用的是哪一版能力方差），解释差 0.01–0.11 的来源与量级是否合理，
  并给出**我方应当采用哪个口径**的明确建议（若建议改口径，请说明改动会影响哪些输出）。
