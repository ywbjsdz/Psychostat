## 一、统计验证（最重要）

1. **P1｜SPSS 对照缺外部基准夹具**。`tests/fixtures/spss/` 目前只有说明，没有任何真实 SPSS 输出。
   现有对照依据是一份手工校准文档（根目录 `SPSS与Psychostat心理统计模块输出对应.docx`），它证明"曾经对齐过"，但**不进 CI、不能防回归**。
   待办：按 `tests/fixtures/spss/README.md` 的流程把各方法 SPSS 数值表存成 `<方法名>.txt`，并加断言。
2. **P1｜承载 SPSS 口径的代码路径缺数值断言**（**大部分已解决**）。断言总数已由当时的 23 条增至 **88 条**，
   其中第 6、9、10 节**直接调用生产函数**并比对可闭式独立求出的值：
   Type III 平方和（非平衡 2×2）、均值中心 Levene、Welch t 的 df、LSD/Bonferroni 的事后 CI 与调整 p、
   球形校正 ε 的结构性质、缺失值删除人数、调节效应的均值中心化口径。
   **仍未覆盖**：非参数渐近 Z（Mann-Whitney / Wilcoxon / Kruskal-Wallis 的结点校正 Z）。
   待办：为这几个方法补"调用生产函数 + 与闭式 Z 比对"的断言。
3. **P1｜Brown-Forsythe 夹具无鉴别力**。`tests/test_numeric.R` 的 BF 用例是平衡数据，此时 BF ≡ 普通 F（4/9 两者相等）。
   待办：换成**非平衡数据**的夹具，使 BF 与 F 不同。
4. **P2｜IRT 的"预期数值"未被断言**（**部分已解决**）。`smoke_test.ps1 -Full` 原本只检查文件是否存在，
   现已加入两条真正断言数值的端到端检查：**2D CIFA-MGRM**（断言 BIC/CFI/RMSEA 的方向与幅度、
   且 CIFA 的 BIC 不得差于单维）与**单维 GPCM 参数表**（断言 `MDISC == sqrt(Σaⱼ²)`、台阶列齐全、b 值有限）。
   **仍未断言**：`examples/simulated_mirt_2pl_binary_expected_output.md` 里那 8 个具体实测值
   （BIC 5656.681 vs 5808.759、CFI 1.000 vs 0.746、RMSEA .000 vs .095、SRMSR .033 vs .095 等）。
   待办：按独立样本 t 的写法把这 8 个数补进 `-Full` 自检。
5. **P2｜θ 恢复指标未脚本化**。README 与模拟数据说明中的"θ 恢复 r ≈ .92"等结论，仓库里没有任何代码计算
   `cor(估计, 真值)`、RMSE、bias 或 CI 覆盖率。本轮为写文档**临时算过一遍**
   （IRT-G/H/I 的 a/b/c/θ 恢复值已写进 `examples/simulated_datasets/README_模拟数据说明.md` 的 2.12–2.14 节），
   但那些数字仍是一次性产出的，**没有脚本、不能复现、也没进 CI**。
   待办：把恢复指标写成 `scripts/` 下的正式脚本（读 `*_truth.csv` + `*_item_parameters.csv` + `*_ability_estimates.csv`），
   计算 RMSE/bias/95%CI 覆盖率 + 题目参数 (a, b, c) 恢复 + ≥5 个种子的 Monte Carlo + 基线对照。
6. **P2｜两套模拟器对 d 的定义不一致**。`scripts/generate_simulated_datasets.R` 用 `d = -b·MDISC`（与管线报告口径一致 ✓），
   而 `scripts/irt_common.R` 的内置模拟路径用 `d = -b·a_primary`（只用主维度载荷）→ 内置模拟下"真值 b"与"报告 b"不可直接比较。
7. **P2｜IRT 非 CIFA 路线不算参数 SE**。`SE=TRUE` 只在 CIFA 拟合时使用，Rasch/2PL/GRM/MIRT 的题目参数表没有 SE/CI。
8. **P2｜mirt / lavaan 的警告级问题被吞掉**。只捕获 error，未检查 `converged` 标志、Hessian 是否正定、参数是否触界。

## 五、IRT 专章（全流程走查新增，均未修）

    里的 F1/F2/F3 与生成/理论维度**不一一对应**（实测同一份三维 GPCM 数据：EIFA 的逐因子 θ 恢复
    *r* = .41/.49/.40，CIFA 则是 .94/.93/.94）。用户很可能把这些列直接当成"理论维度分数"拿去用。
    待办：EIFA 路线的报告与文件说明里加一句"因子已旋转，逐因子比对前需先做因子匹配"；
    或输出因子相关矩阵辅助人工匹配。（现象已写进手册 §6.9，但工具层面仍无提示。）
    > 2026-09-18 补：这两组数字现已由 `tests/verify_recovery_irt.R` **可重复产出**
    > （实测 EIFA r = .395/.486/.407，CIFA r = .943/.933/.941），不再依赖一次性脚本。
39. **P3｜`Primary_dimension` 在多维下输出的是列名而非维度名**。MGRM/MGPCM 的 `*_item_parameters.csv` 里
    这一列取值是 `a1` / `a2`（单维才给 `F1`），而 CIFA 路线的 `*_cifa_loading_matrix.csv` 用的是 F1/F2。
    两份表对同一件事用了两套标签。待办：统一成维度名（CIFA 用对照表里的名字，EIFA 用 `F1..Fk`）。
40. **P3｜单维模型的 `*_ability_estimates.csv` 列名是 `F1`，真值文件用的是 `Theta`**。
    做参数恢复时要手动映射（本轮写分析脚本时就踩到 `KeyError: 'Theta'`）。待办：二选一统一。
41. **P2｜3PL 的 `c` 是弱识别参数，但表里看不出来**。实测（N=1500、20 题、真值 c ∈ [0.08,0.25]）：
    c 的均值几乎无偏（.168 vs .171），但**逐题恢复 *r* = −.406**——排序完全是乱的。
    而 `*_item_parameters.csv` 会把逐题 `g` 平铺直叙地写出来，没有任何 SE 或警示
    （与第 7 条同源：非 CIFA 路线不算参数 SE）。
    待办：至少在报告里对 3PL 加一句"c 为弱识别参数，个体差异不宜解读"，或在表里标注。
    > 2026-09-18 补（第三方复核提出 `ltm::tpm` 对照后本机复现）：工具与 `ltm::tpm` 的 c
    > 相关 **r = 0.9755**（平均差 −0.0011），即**两个独立实现互相吻合**；
    > 但分别对真值比对，工具 r = −0.4064、`ltm` r = −0.3638，**两个实现都恢复不了真值**
    > （真值域 [0.087,0.242] 很窄，两者估计域 [0.01,0.58] 很宽），`ltm::tpm` 同时报
    > `Hessian not positive definite`。**实现间一致 ≠ 参数可信**：这条对照只能证明"无实现缺陷"，
    > 不能作为"逐题 c 可用"的理由。报告措辞应按此两面写。
42. **P2｜`allow_3pl` 默认 false，导致 `auto` 永远不会考虑 3PL**。即便 N ≥ 1000 也一样——
    只有用户显式改配置、或显式写 `model: 3pl`，3PL 才会被拟合。这个默认值是否合理值得再想
    （文档已说明其作用范围，但"默认不启用"与"手册建议 N≥1000 可用"之间仍有张力）。
