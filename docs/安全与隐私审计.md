# 安全与隐私审计（v0.1.0 内测版）

**审计日期**：2026-09-19　**范围**：整个项目仓库（含所有启动器、GUI、R/Python 计算与报告层、打包脚本）
**审计方式**：全量静态审查（关键字扫描 + 逐行阅读高风险文件）+ 对产物做实证检查
**审计人声明**：本人参与了本项目的测试与校对工作，**不是独立第三方**；本次是静态审计，
**不是渗透测试**，也未做依赖库的 CVE 扫描。以下结论按"证据 → 影响 → 建议"给出，可逐条复核。

---

## 一、总的结论

| 问题 | 结论 |
|---|---|
| 会不会把用户数据传到网上？ | **不会。** 全仓**没有任何**上传/回传/遥测/邮件/webhook 代码，没有 API Key，没有分析统计 SDK。 |
| 有没有 AI 接口在后台读数据？ | **没有。** GUI 的「用 AI 助手协助」只是 `Start-Process notepad.exe AI智能体工作流.md`，打开本地说明文件；产品不调用任何大模型。 |
| 有没有凭据泄露风险？ | **没有。** 无硬编码密钥/口令；`git` 内无 `.env`、无凭据文件、无数据文件误提交。 |

## 二、逐项排查结果（先说没问题的部分）

### 2.1 数据外传：干净

- 扫描 `Invoke-WebRequest|Invoke-RestMethod|WebClient|HttpWebRequest|curl|wget|Upload*|Send-MailMessage|smtp|webhook|telegram|feishu|dingtalk|sentry|analytics` →
  命中仅 `psychostat_env.ps1` 的**下载**代码（下载 R/Python 安装包），**没有任何 POST/上传/回传**。
- 全仓出现过的域名**只有**：`cloud.r-project.org`、清华 TUNA、中科大、阿里云、华为云、`pypi.org`、`pypi.tuna`、`registry.npmmirror.com`、`www.python.org`，以及文档里的 `doi.org` / `semver.org` / `keepachangelog.com`。
  **没有任何第三方服务域名**（无网盘、无统计、无 AI 网关）。
- `启动AI智能体工作流.bat` 与 GUI 按钮：都只是**用记事本打开** `AI智能体工作流.md`；该文档明确写着"不需要也不会保存 API Key"。

### 2.2 凭据与密钥：干净

`grep -i "api[_-]?key|secret|password|token|credential|Authorization|sk-…|ghp_|AKIA"` →
唯一命中在 `tests/thirdparty/round2/review_round2.R`，那是复核脚本里名为 `token` 的**字符串匹配变量**，与凭据无关。
`git ls-files` 中无 `.env` / `*.pem` / `id_rsa` / `*.key`。

### 2.3 动态执行：干净

无 `Invoke-Expression` / `iex` / `ScriptBlock]::Create` / `eval(parse(...))` / `eval(str2…)`。
R 侧只有 `do.call(rbind, …)` 这类正常用法；列名进入公式前已被安全化（`rename_for_formula`）。
→ **不存在"数据内容被当代码执行"的通道。**

### 2.4 提权与系统改动：干净

无 `RunAs` / `-Verb RunAs` / 清单要求管理员；无 `New-Service` / `schtasks` / `netsh` / `diskpart` / `Format-Volume`；
无 HKLM 注册表写入。安装目标按文档为 `D:\`、`%LOCALAPPDATA%`，**用户级、免管理员**。

### 2.5 破坏性操作：只在一处，且护栏扎实

全仓唯一递归删除在 `scripts/uninstall_psychostat.ps1`（`:215`）。逐行审查后认为**设计良好**：

- **叶子名白名单**：只允许删 `Psychostat-R-Library` / `Psychostat-Python-User` / `PsychostatTemp`
  → 即使清单被篡改成任意路径，也会因目录名不在白名单而被**拒绝**（报告里显示 `[拒绝]`）。
- 另外三重判断：不是盘根、路径长度 ≥ 12、**不在项目目录内**。
- **默认只预览**；需要 `-Execute`；非交互环境（管道/CI）**只预览、绝不删除**；`-Force` 才跳过确认。
- **红线明确**：不删 R/Python 本体、不删共享用户库（哪怕清单记录了"是本工具装的"）、
  **不删 `outputs/` 与 `data/`**（只在预览里列出体积提醒你自己处理）。

### 2.6 写入范围：不碰用户原始数据

所有写文件调用都走结果目录或临时目录（`fn(...)` / `out_dir` / `ctx$out_dir`）。
用户选定的输入数据文件**只读不改**；未发现把结果写回输入文件的路径。
报告层（Word/HTML）**不嵌入完整作答矩阵**（`*_data.csv` 被显式排除）。

### 2.7 仓库卫生：干净

无凭据文件；88 个 CSV 全部位于 `examples/`、`tests/` 下（即模拟数据与测试夹具），**没有真实数据入库**。

## 三、需要处理的问题

### 3.1【中】HTML 结果报告内嵌"被试级明细表"，且含 ID 列

**证据**

- `scripts/generate_html_report.py:1115-1116`：把 `01_case_cleaning_audit.csv` 作为
  「逐被试清洗审计」表格写入报告，`max_rows=200`。
- `scripts/generate_html_report.py:1248`：把 `person_missingness.csv` 作为
  「逐被试缺失概览」表格写入报告，`max_rows=100`。
- 实证：`outputs/ctt_B_ctt_20260918_080516/ctt_report_zh.html` 中该表**首行即出现被试编号 `P001`**；
  IRT 的 `irt_report_zh.html` 同样含「逐被试缺失概览」表。
- 对照：**Word 报告不含**被试级表（`generate_result_reports.py`、`generate_ctt_report.py` 中
  对这些文件的引用数为 0；实测 `ctt_report_zh.docx` 全文无 `participant_id`）。

**影响**：这是**分享场景下的数据外泄脚点**——学生把 HTML 报告发给老师/同学、或贴到网上求助时，
报告里已经带着被试级行（含 ID、缺失/注意检验/过快作答等标记）。
一份"看起来只是结果报告"的文件，实际是一份可识别到个体的数据表。
产品本身**不联网**，因此这不是"被上传"，而是"你主动分享时无意中分享"。

**建议（任选，可组合）**

1. **默认遮蔽 ID 列**（保留行结构，把 `participant_id` 替换为 `P***` 或行号）；
2. 这两张表**默认改为汇总**（只给"被删除人数、各类标记人数与比例"），明细放入 CSV 并在报告里注明文件位置；
3. 至少在含该类表格的报告**顶部加一条醒目提示**："本报告含被试级明细，对外分享前请删除这两张表"；
4. 若希望与 Word 报告口径一致，可直接与 Word 报告对齐（不嵌入被试级表）。

> 同一件事也建议写进 `内测须知与免责声明（必读）.txt`：**结果目录的 CSV（`01_cleaned_items.csv`、
> `*_ability_estimates.csv`、`*_person_missingness.csv`、`01_case_cleaning_audit.csv`）含被试级数据，
> 对外分享前请自行脱敏**——目前免责声明只说了"真实数据请备份"，没有说这一点。

### 3.2【中】自动安装 R/Python 时不校验安装包完整性

**证据**：`psychostat_env.ps1:501,520`（R）与 `:319,336`（Python）——
下载到 `%TEMP%` 后用 `Start-Process … /VERYSILENT /SUPPRESSMSGBOXES` **静默执行**，
全程**没有** `Get-FileHash`、没有 `Get-AuthenticodeSignature`、没有与官方发布的哈希比对。
R 安装包来自镜像（`$m/bin/windows/base/R-…win.exe`），Python 安装包候选含 `registry.npmmirror.com` 与华为云镜像。

**影响**：仅在"用户没有 R/Python 且同意自动安装"时触发；走的是 HTTPS，被动窃听已被缓解；
但如果某个镜像被投毒或劫持，**会在用户机器上静默执行一个未经校验的安装程序**。
这是整个项目里**安全等级最低的一环**。

**建议**：下载后先校验再执行——`Get-AuthenticodeSignature` 检查发布者是否为
`R Foundation` / `Python Software Foundation`，或比对官方公布的 SHA256/MD5；
校验失败则中止并提示用户手动到官网安装（并给出官网链接）。

### 3.3【低】自动装包不按锁定版本，且来源为镜像

**证据**：仓库有 `renv.lock`（R 版本已锁定）与 `requirements-lock.txt`，但运行期自动安装走
`install.packages(p, repos = rp)`（`psychostat_env.ps1:260`），**取的是当时的最新版**，不读 `renv.lock`。
镜像是 `cloud.r-project.org` / 清华 TUNA / 中科大 / 阿里云。

**影响**：不是安全漏洞，是**可复现性**问题——不同时间安装会拿到不同版本，
这会影响"结果能否逐位复现"（本项目的自行验证是在固定版本上做的）。
**建议**：文档里说明"结果差异可能来自包版本"，或将 `renv.lock` 纳入自动安装路径（可选）。

### 3.4【低】`%TEMP%` 的数据体检文件从不清理，且含列名与缺失统计

**证据**：`%TEMP%` 下实测**已累积 231 个** `irt_preflight_*.json`（自 2026-09-06 起）。
内容为元数据：样本量、题目数、计分类型、逐题缺失数、零方差列名、`detected_items`。
**不含任何作答值**（已逐字段确认）。

**影响**：低。不含数据值，但**含变量名与缺失结构**——若用户把这个文件发给别人（内测须知正是
让用户回传这类文件），会连带泄露变量名。**建议**：启动器收尾时删除自己产生的临时文件；
内测须知里说明"回传前可先看一眼是否含敏感列名"。

### 3.5【低】`AI智能体工作流.md` 鼓励把数据交给第三方 AI，但缺隐私警告

**证据**：该文档指导用户"向已登录的 AI 助手上传：原始数据文件、变量说明…"。
产品自身不联网，但这份**文档**等于在引导用户把数据传到外部 AI。

**影响**：在当前外部 AI 服务频出隐私争议的背景下，这是最容易被诟病的一点（"你们的文档让我传数据"）。
**建议**：在该文档顶部加一段强制提示——**先删除姓名/学号/身份证/联系方式等直接标识列**；
能用汇总统计就不用原始数据；并注明"上传即离开你的电脑，风险自负"。

### 3.6【低】分发包内嵌了你的 Windows 用户名与本地绝对路径

**证据**：对最终 zip（`Psychostat v0.1.0.zip`）逐文件扫描，**7 个文件**含 `C:\Users\<你的用户名>\…`：

- `docs/第三方AI复核提示词_CTT与IRT.md`、`docs/第三方AI复核提示词_第二轮_CTT与IRT.md`
- `docs/第三轮_CTT与IRT审查报告.md`、`docs/第三轮_G1-G3补充审查报告.md`
- `tests/thirdparty/round2/ctt_B_round2_config.yaml`
- `tests/thirdparty/round2/results/ctt_B_round2_ctt_20260918_192928/config_snapshot.yaml` 与 `run_manifest.json`

**影响**：**朋友内测无影响**；但一旦把包传到网盘、GitHub、课程群或作为论文附件公开，
你的 Windows 账户名与本地目录结构就会随包泄露（社工面信息）。这与"用了哪个 AI"无关，
而是**发布前的产物卫生**问题。

**建议**：对外公开前，把这 7 个文件里的用户名替换为占位符（如 `<user>`）——
或更简单：公开版只保留 `docs/` 下的正式说明与结果文档，**不随包分发 `tests/thirdparty/` 复核证据**
（那部分属内部过程材料）。

### 3.7【提示】其余两点（不必改，知情即可）

- `tests/verify_*.R` 里存在 `list.files(ROOT, recursive = TRUE)` 的**全仓递归扫描**（用于定位原始数据）。
  在仓库内运行无害；但如果有人把 `ROOT` 指到别处，会遍历较大目录。属测试脚本，非产品路径。
- 配置里的 `output.directory` 可指定任意可写路径（用户自定，属设计）。
  **共享他人给的配置文件时需留意**它会把结果写到哪。
