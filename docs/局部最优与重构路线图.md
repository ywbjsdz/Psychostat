## 1. 补丁式修改（局部最优的典型形态）

> 特征：问题在**症状处**被按住，而不是在**根因处**解决；因此同类问题会在别处复发。

**A1【中】`Format-Fatal` 只加在 IRT 启动器里**
- 证据：`grep "function Format-Fatal"` → 只在 `run_irt_analysis.ps1` 命中。
- 后果：**同一个"准确中文提示被翻译成套话"的问题在 CTT 与心理统计分支仍然存在**。
  实测：CTT 用 0–4 编码却声明 `scale_maximum: 5` 时，R 已明确打印
  `Reverse scoring assumes 1..scale_maximum …`，但启动器只回一句
  「R 分析未完成。请检查数据列名、量表计分和配置」——**用户看不到真正的原因**（需加 `-Verbose` 才行）。
- 根因：修复时只改了当时出问题的那一个启动器（典型的"就地打补丁"）。

**A2【中】`selected_model_label` 的四处特判**
- 证据：`scripts/irt_generic_pipeline.R` 里
  `selected_model_label <- if(is_mirt && mirt_mode=="eifa") … else if(is_mirt && mirt_mode=="cifa") "CIFA" else chosen_name`。
- 后果：这条三元链每加一种路线就要再补一个分支（历史上已补过两次）；推荐表的 `Selected` 与实际模型
  曾不一致（已修，但修法是再加分支）。更稳的做法是让"实际使用的模型"只有一个来源（见 P1-3）。

**A3【低】GPCM 的 `ak*` 列识别靠"列名正则 + 特判"**
- 证据：`acols <- grep("^a[0-9]+$", …)`、`if(any(grepl("^ak[0-9]+$", …)) && length(dcols)>1L)`。
- 后果：依赖上游 `mirt::coef()` 的列命名约定；上游改一次名就静默出错（历史上真出过：`MDISC=5.536` 那次）。

**A4【低】"静默模式只接受 JSON 配置"这类契约写在启动器内部**
- 证据：`run_irt_analysis.ps1:122`、`run_ctt_analysis.ps1` 各自实现一份校验与报错文案。
- 后果：三条分支的静默契约靠"人记住同步"，已出现措辞与行为不一致。

**A5【低】CTT/IRT 各写一份"安全列名"逻辑**
- 证据：`ctt_pipeline.R` 的 CFA 语法安全名、`irt_generic_pipeline.R` 的 CIFA 安全名、
  以及 `formula_name_mapping()`，三处都在解决"列名不是合法 R 变量名"这同一个问题。
- 后果：CIFA 那次"题名口径不一致"缺陷（`Item1` vs `Item01`）正是这种分散实现的产物。

| 函数 | stats | ctt | irt | psychostat_env.ps1 |
|---|---|---|---|---|
| `Write-Stage` | 1 | 1 | 1 | 0 |

| `Stop-Friendly` | 1 | 1 | 1 | 0 |
| `Translate-RFailure` | 1 | 1 | 1 | 0 |

| `Resolve-ExistingPath` | 1 | 1 | 1 | 0 |
| `Format-Fatal` | 0 | 0 | 1 | 0 |

合计 **18 处重复定义**。三者已出现行为漂移（`Format-Fatal` 只在 IRT）。
三份实现里还各有一份"翻译表"，内容互有出入——**用户在不同分支看到不同的报错质量**。

**B2【中】R 包清单（同一事实 5 份副本）**
`run_stats_analysis.ps1:275`、`run_ctt_analysis.ps1:90`、`run_irt_analysis.ps1:124`、
`requirements.txt` 的注释、`docs/CTT使用说明.md`。改一个包要改五处，漏一处就是"文档说装了、实际没装"。

**B3【中】镜像列表写两遍**
`psychostat_env.ps1` 的 R 包安装代码里（4 个 CRAN 镜像）与 `Install-PsychostatR` 的镜像数组各一份，
顺序与集合还不完全一致。

**B4【低】"读 CSV 并容错"在两个 Python 报告生成器里各一份**
`generate_html_report.py` 有 `read_csv_relaxed()`，`generate_stats_report.py` 有 `read_csv()`，
容错策略（编码、空表、缺列）不同 → 同一份 CSV 在 Word 与 HTML 里可能出现"一个有一个没有"。

**B5【低】三个 `.bat` 的"启动 PowerShell"样板**
`启动心理统计.bat` / `启动量表编制_CTT.bat` / `启动项目反应理论_IRT.bat` 结构相同，仅目标脚本不同。

## 4. 上帝对象

**D1【中】`scripts/psychostat_gui.ps1`：2146 行单文件**
同时承担：窗口与布局、左侧导航、四套步骤面板、三条分支的任务脚本**字符串拼装**、

## 6. 异常吞噬

| 类型 | 处数 | 危险样例 |
|---|---|---|
| `-ErrorAction SilentlyContinue` | 47 | 大多合理（探测路径、删临时文件），但 `psychostat_env.ps1` 里若干处包住的是**安装与写入**动作 |
| `tryCatch(…, error = function(e) NULL)` | 20 | `irt_generic_pipeline.R` 里包住 `M2()`、`itemfit()`、`coef()`；失败后表里只是缺列/NA，**用户不知道是"没算"还是"算不了"** |
| 空 `catch { }` | 29 | GUI 与 env 脚本中的静默兜底 |

最需要处理的是 **F1**：`fit_statistics()` 用 `tryCatch` 包 `M2()`，失败即 `M2=NA`；
而 CIFA 路线的 M2 本来就常为 NA——**"算不出来"与"模型不拟合"在输出里无法区分**。
建议：保留 NA，但同时在结果目录写一张 `*_computation_notes.csv`（哪一项、为什么跳过），让"缺失"可解释。

## 7. 测试不足

**G1【高】21 个统计方法里只有 6 个有数值断言**（项目方自述，`docs/待修问题清单.md` 第一节）
→ 其余 15 个模块的数值正确性没有任何自动保护；改动共享代码（如 `stats_common.R`）时**无法知道谁被改坏**。

**G2【高】报告层（Word/HTML）零测试**
`tests/` 下没有任何针对 `generate_*_report*.py` 的测试。
实际后果已经出现两次：① 调节效应的 `UnboundLocalError`（`p1` 未初始化）导致整份报告出不来；
② HTML 报告内嵌被试级编号（隐私问题）——**两者都是"没人测过报告层"的直接产物**。
> 现已加的 `_guarded()` 只保证"不崩"，不保证"内容对"。

**G3【中】启动器/环境层几乎没有测试**
`tests/` 里与启动器相关的只有冒烟测试的几条；"检查环境/自动安装"这类**网络 + 安装**路径完全没有测试，
所以"点很久还装不上"只能靠用户反馈发现（见第八节）。

**G4【中】GUI 无自动化测试**
只有几条内嵌自检（如 G4 白名单解析），界面本身不可回归测试。

## 8. 附带：本次顺带查清的一个用户可见问题（与上面 B1 同源）

**"检查环境/自动安装"按钮名不副实**：

- 它调用 `Initialize-PsychostatEnvironment -AllowAutoInstall`（**只做：找 R → 设库路径 → 重定向 TEMP → R 自检**）
  与 `Initialize-PsychostatPythonEnvironment`（**会真的下载并安装 Python**）。
- 它**不安装任何 R 包**——R 包的安装发生在**三个启动器各自的启动阶段**
  （`Get-PsychostatPackageInstallScript` + 镜像测速 → 只装缺的）。
- 于是出现用户观察到的现象：**点完按钮 → 再点开始分析 → 仍然下载一堆 R 包**，
  按钮看起来"没用"；而"很久很久"主要来自 **Python 的下载与安装**（约 25 MB 安装器 + pip 装 pandas/python-docx）。
- 结论：**这是命名与职责不一致**，不是安装失败。设计与修法见第九节。

## 9. 分阶段重构路线图

> 原则：**每一步都可独立验证、可回退**；不改 R 统计算法、不改任何输出文件的列名/口径/数值；
> 每阶段必须先建立"改动前后输出逐字节一致"的对照手段。

### 阶段 P0（本次执行）：消灭启动器重复，顺带修掉 A1

- **动作**：把 6 个重复辅助函数（`Write-Stage` / `Write-JsonLog` / `Stop-Friendly` /
  `Translate-RFailure` / `ConvertTo-Utf8Hex` / `Resolve-ExistingPath`）与 `Format-Fatal`
  **收进已被三个启动器 dot-source 的 `psychostat_env.ps1`**；
  各启动器删除本地副本。合并时取三份实现的**并集**（翻译模式取并集，绝不删任何一条既有模式）。
- **为什么不改行为**：函数体逐字搬运 + 取并集；`Format-Fatal` 对三个分支生效属于**修缺陷**，
  且只影响"错误提示文字"，不影响任何计算与输出文件。
- **验收**：
  1. 三条分支各跑一次 `-Silent -ConfigJson`，**JSON 事件序列逐字节一致**（除时间戳）；
  2. `smoke_test.ps1 -Full` → ALL CHECKS PASSED；`test_numeric.R` → PASS_COUNT 不变；
  3. 复现 CTT 的 0–4 编码场景 → 错误提示应给出 R 的**具体原因**（修 A1 的证据）；
  4. 三个 `.ps1` 仍满足"UTF-8 + 恰好一个 BOM"（由冒烟测试强制）。

### 阶段 P1（建议下一轮）：把"同一事实"收敛到单一来源

- **P1-1** R 包清单 → 一处定义（放 `psychostat_env.ps1` 的 `Get-PsychostatRequiredPackages -Branch`），
  启动器与 `requirements.txt` 由它派生或至少由测试断言一致。
- **P1-2** 镜像列表 → 一处定义（`$script:PsychostatMirrors` + 可选覆盖）。
- **P1-3** `selected_model_label` → 改为从"实际使用的模型"单一来源派生，删掉三元特判链。
- **P1-4** 两个 Python 报告生成器共用同一个 `read_csv_relaxed`（从 `generate_stats_report` 导出）。
- 验收：新增一个"包清单一致性"断言；三条分支的输出与 P0 前后逐字节一致。

### 阶段 P2（建议再下一轮）：测试补到关键路径

- **P2-1** 先补**共享代码**的测试（`stats_common.R` 的格式化/门槛函数），再补 21 个模块里
  调用共享代码最多的那几个（优先 `normality`、`correlation`、`regression`）——按"改动风险"排序，
  而不是按编号顺序。
- **P2-2** **报告层测试**（G2，最高优先级）：给定一个固定结果目录，断言
  "报告里出现的每个统计量都能在 CSV 里找到""报告不含被试级编号""缺表时只跳过该节且不崩"。
  这一条能同时防住已经发生过的两个缺陷。
- **P2-3** 环境/安装路径的"离线可控"测试：把网络调用抽成一个可注入的函数，用假响应测试
  "缺包→装→仍缺→报错"的各分支（不需要真联网）。

### 阶段 P3（记录在案，暂不做）

- GUI 拆分（D1）与 `stats_modules.R` 拆分（D2）：收益是维护性，风险是**大面积改动**，
  在内测期不值得；建议等接口稳定（数值断言覆盖率上来之后）再做。
- 异常吞噬治理（第六节）：先把"静默降级"变成"显式记录"（写 `*_computation_notes.csv`），
  再逐步收紧 `catch {}`。**不要一次性把所有 `SilentlyContinue` 改成 Stop**——那会让工具在
  无关紧要的探测失败时整体崩掉。

### 明确不做（避免过度重构）

1. 不动任何 R 统计算法与阈值取值；
2. 不改任何输出文件的文件名、列名、列序、数值与文案口径；
3. 不引入新依赖（不引 Pester、不引 R6/box 之类框架）；
4. 不重写 GUI、不换语言、不合并三个分支。

1. **静默 JSON 契约逐字不变**：三条分支各跑一次 `-Silent -ConfigJson`，事件序列与事件体在剔除

3. **回归套件**：`smoke_test.ps1 -Full` → ALL CHECKS PASSED；`test_numeric.R` → PASS_COUNT=93 FAIL=0；
   4 个核心 `.ps1` 通过 PowerShell 语法解析；编码契约（单 BOM）保持。
4. **缺陷 A1 已修**（本次唯一有意的可见变化）：CTT 分支的报错不再只说套话——
   实测 0–4 编码反向计分的场景现在提示
   `R 分析未完成。请检查数据列名、量表计分和配置（原始错误：Error: Reverse scoring assumes 1..scale_maximum, but observed responses range 0..4 while）`。
